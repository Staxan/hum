# hum — каталог моделей UnoRouter с подключением к агентам Hermes

Веб-интерфейс каталога моделей UnoRouter. Напротив каждой модели — кнопка **«Подключить»**:
выбираешь агента, модель записывается в его `config.yaml`, gateway перезапускается.

## Установка

```bash
hermes plugins install Staxan/hum
```

Зависимостей нет — только стандартная библиотека Python. Поднимать ничего не нужно:
плагин стартует вместе с gateway.

Открыть: **http://127.0.0.1:8780/**

## Что умеет

- **Каталог** как на unorouter.com: цены ввода/вывода, скидки, контекст, доступность,
  успешность, задержка, дата выхода, провайдер, теги.
- **Фильтры**: модальность, бесплатные/платные, контекст от N, цена ввода/вывода до N,
  инструменты (tools/vision/reasoning/cache), только доступные, провайдер, поиск, сортировка.
- **★ Избранное** — первым столбиком, модель закрепляется вверху, переживает рестарт.
- **Проверить** — один короткий запрос к модели. Только бесплатные: платные кнопка отключена,
  чтобы не расходовать баланс. Текст запроса случайный из пула общих вопросов.
- **Обновить данные** — перезапрос цен и доступности.
- **Проверить все бесплатные** — массовая проверка с подтверждением.
- **Подключить** → выпадающий список всех профилей-агентов с их текущей моделью.

## Как устроено подключение

1. Профиль агента ищется в `~/.hermes/profiles/<name>`, дефолтный — в `~/.hermes`.
2. `model.default` пишется в его `config.yaml` через `atomic_yaml_write` (атомарно).
   Перед записьм создаётся бэкап `config.yaml.hum-backup-<метка>`.
3. Сбрасывается `model_override` в `sessions.json` — сессионный override имеет приоритет
   над конфигом, иначе старый ручной `/model` победил бы свежее значение.
4. Выполняется `hermes gateway restart [--profile <имя>]`.

### Почему модель пишется прямо в конфиг, а не через `${VAR}`

Проверено живьём: gateway читает конфиг через `read_raw_config()`, который **не раскрывает**
переменные окружения. Плейсхолдер `${env:UNOROUTER_MODEL}` доезжает до него строкой:

```
GATEWAY model -> '${env:UNOROUTER_MODEL}'
```

Раскрытие есть только в `load_config()`, которую путь gateway не использует. Поэтому
`model.default` содержит literal. Само значение меняется атомарно — файл цел в любой момент.

## Порты и доступ

Слушает **127.0.0.1:8780** — только локально. Порт меняется переменной `HUM_PORT`.
Входа нет: сервис не выставлен наружу.

Диапазон 8644-8648 занят служебными портами Hermes, поэтому плагин намеренно его не
использует: иначе сервис получил бы чужой сокет и молча отдавал бы не свои ответы.

## Источники данных

- **Цены, контекст, скидки, успешность, задержка** — встроенный JSON страницы
  `unorouter.com/ru/модели`. Публичного API с ценами у UnoRouter нет.
- **Список id и провайдер** — `api.unorouter.com/v1/models` по ключу профиля.

Если страница не читается, каталог показывает прошлые данные с пометкой ⚠, а не пустоту.

## Ключ UnoRouter

Берётся из `UNOROUTER_API_KEY`, иначе из `model.api_key` в `config.yaml` профилей.
Нужен только для списка моделей и проверки; каталог с ценами работает и без него.

## Известные нюансы

- Модель может быть в каталоге сайта, но отсутствовать в API шлюза — тогда проверка вернёт
  `model_not_found`. Это честный ответ шлюза, не ошибка плагина.
- У части бесплатных моделей дневной лимит у провайдера (`HTTP 429`) — кнопка покажет это.
- `hermes plugins doctor` проверяет совместимость плагина с текущей версией Hermes.

## Структура

```
plugin.yaml        манифест плагина
hum_plugin/
  __init__.py      точка входа: сервер + инструменты агента
  catalog.py       сбор каталога (страница + API)
  model_check.py   проверка модели одним запросом
  connector.py     профили, запись config.yaml, рестарт
  favorites.py     избранное (SQLite)
  server.py        HTTP API + статика
web/               интерфейс (index.html, style.css, app.js)
```

Инструменты агента: `hum_models`, `hum_connect`, `hum_status`.
